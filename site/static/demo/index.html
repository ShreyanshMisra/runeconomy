Intervention Tested

vLLM can reuse cached prompt tokens while a new prompt matches a previous prompt from the beginning. In the baseline, changing metadata appeared first, so the shared prefix ended immediately. The candidate moved that metadata after the stable instructions.

Why this might help: A longer stable prefix may allow more prompt tokens to be reused from cache.

Control: The prompt content stayed the same. Only the block order changed.

Verdict

Result not verified

The candidate showed better cache reuse and lower measured latency, but this experiment did not establish the task-quality evidence required for a verified performance claim.

Verdict: Invalid

Experiment Details

Each task gave the agent a code clue and a bounded set of repository files. The agent planned a search, used a repository-search tool and identified the enclosing Python function or class.

Experiment factRecorded value
Task families13 direct-call lookup tasks, 13 docstring lookup tasks and 14 unique-string lookup tasks

Workflow2 model calls and 1 repository-search tool call per attempt
EnvironmentQwen2.5-7B-Instruct, vLLM 0.33.0, Modal A10
ExecutionChat Completions, colocated driver and sequential execution

Supported claimRunEconomy rejected an apparently faster, more cache-efficient candidate because the frozen successful-task quality requirements were not established.
Claims not supporteda verified performance improvement, universal model behavior, production-concurrency performance, superiority over another tool
LimitationsOne pinned model revision, vLLM version, A10 hardware class, and repository-analysis workload were evaluated. Execution was sequential and colocated. Production concurrency and multi-replica routing were not tested. Continuous effects use only the 36 task pairs where both variants succeeded. Workflow latency includes process startup and agent execution but excludes evaluator time. Prefill, decode, retrieval, cost, and GPU-time effects were unavailable and remain unknown rather than zero. The 40-task held-out workload is consumed and cannot be reused as fresh held-out evidence. External readers can audit the aggregate arithmetic, gate logic, provenance hashes, and claim boundary, but cannot independently recompute the experiment without the private raw tasks and traces.
